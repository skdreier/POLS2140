## Core conventions (always in force)

- **Format:** every deck uses `format: clean-revealjs` (the `grantmcdermott/clean` extension), `self-contained: true`, `slide-number: true`. Copy the YAML block from an existing deck or `sarah_slide_template.qmd` rather than writing it from scratch.
- **Standard opener:** every deck (from-scratch or converted) opens with two blank slides, in this order — `## Reading Prompt`, then `## Announcements` — left empty; filled in by hand each time the deck is actually taught. No "Wrap up from last class" slide.
- **Standard closer:** immediately before `## TL;DR {.smaller}`, add a **next-class reading slide** — heading style `## For [Day]:` (matches the existing "For Thursday:" / "For Tuesday:" pattern), naming the next class meeting's assigned reading(s), sourced from and verified against the syllabus's Course Schedule (`New_2140_syllabus/POLS2140_Syllabus_F26.qmd` — never invented), and linking to the published syllabus (`https://skdreier.github.io/POLS2140/`) so students can click through to the full schedule. Then `## TL;DR {.smaller}` (3–5 genuine takeaways generated from *that lecture's actual content*, never generic/padded), then a `## References {.smaller}` slide — always include the References slide, even if it's the only citation in the deck.
- **Citations — use `@key`, never hand-written links or plain "(Author Year)" text** for a source attribution. Add the entry to `references_2140.bib` if it isn't there yet (`bibliography: references_2140.bib` + `csl: apa.csl` in the YAML; do **not** set `biblio-title:` — it collides with a manual `## References` heading and suppresses it). Forms: `[@key]` parenthetical, `@key` narrative, `@key [p. 12]` / `@key [Fig. 2, p. 346]` with a locator. Put a figure-source line in a fenced div (`::: {style="..."}`), not a raw `<div>` — citeproc doesn't process citations inside raw HTML. A memorable in-class nickname the user wants literally clickable (e.g. "Race + Red Cards") is the one case where a direct `<a href>` is fine instead.
- **Pauses:** `. . .` (three dots, own blank-line-separated line) for plain slide markdown. `::: {.incremental}` for a whole list so every item pauses without splitting the `<ul>`. `::: {.fragment}` for a single standalone block, or inside a raw HTML `<div>` (dots are deliberately left alone there and print a build warning). Default to pausing between bullets/lines/images unless the user says otherwise.
- **Emphasis: "emphasize" means `[text]{.hl}`.** When the user says "emphasize" a word/phrase/line, write `[text]{.hl}` — renders teal (`#107895`), bold. Not italics, not `**bold**` alone, not a different color, and not a hand-written `<span style="color: #107895; font-weight: bold;">`. This is the literal, standing definition of the instruction — no need to ask which color, and no need to write out the span. Every deck's YAML defines the class once, in `include-in-header` (same treatment as the link `target="_blank"` script below — copy it into any deck that's missing it):
  ```
  include-in-header:
    text: |
      <style>.reveal .hl { color: #107895 !important; font-weight: 700; }</style>
  ```
- **Secondary emphasis (a callout/warning note, an "important caveat" aside, a researcher-judgment flag) means `[text]{.hl2}`.** Maroon/red (`#9a2515`), bold — the deck's second accent color, for anything that should stand out *differently* from (not instead of) the teal `.hl` (e.g. "you'll need to transform this for this class," "as the researcher you need to make modifications," a term inside a larger `.hl2`-styled sentence still renders teal via `.hl`'s own `!important`, since nested spans layer normally). Not a hand-written `[text]{style="color: #9a2515; font-weight: bold;"}` — same reasoning as `.hl` above: no need to write out the inline style each time. Added to this course's shared vocabulary 2026-09-22 (`10_variable_types.qmd` had already accumulated five hand-written instances of the exact same span before the shortcut was defined). Add the class alongside `.hl` in any deck's `include-in-header` (both live in `sarah_slide_template.qmd` as the reference copy — add it to a deck that's missing it the same way you'd add `.hl`):
  ```
  include-in-header:
    text: |
      <style>
      .reveal .hl { color: #107895 !important; font-weight: 700; }
      .reveal .hl2 { color: #9a2515 !important; font-weight: 700; }
      </style>
  ```
- **Hyperlinks: write `[text](url)`.** The template's `include-after-body` script gives every external link `target="_blank"` at load, so links open in a new tab without a hand-written `<a href … target="_blank">` or a `{target="_blank"}` attribute. A raw `<a>` is still fine where you specifically need it (inside a raw-HTML `<div>`, wrapping an `<img>`). Any deck missing that YAML script should get it.
- **"Reformat slide X to match slide Y" means a literal template copy** — same lines, same bullets, same category labels, in the same order; change only the dataset-specific facts (variable IDs, counts, country/label names). Do **not** restructure, merge blocks, drop content, or reword the prose to "mirror the structure" — that reading has been explicitly rejected. When the target covers one variable and the source two (or vice versa), keep the target's block count and fold the extra items into the existing blocks.
- **Section-divider slides — ALWAYS dark background + white text, no exceptions, and this is AUTOMATIC at render time, not something to remember.** Every full-bleed `#` (single-hash) section-break slide gets the standard slate — a bare `# Course Datasets` needs **zero attributes and zero body-text wrapping** to render correctly. This is enforced by two pieces of shared theme infrastructure in `_extensions/grantmcdermott/clean/` (the same extension that already auto-handles `. . .` pauses via `pause-dots.lua`):
  1. `section-dividers.lua` — a Pandoc filter that injects `background-color="#2c3e50"` onto any level-1 Header (`#`) that doesn't already carry one, at render time. An explicit `{background-color="..."}` the author wrote on purpose is left alone.
  2. A rule in `clean.scss` — `.reveal .slides section[data-background-color="#2c3e50"] { color: #ffffff; }` — that auto-whites every descendant (paragraphs, lists, citations) of any divider slide with that background, so no per-slide `::: {style="color: #ffffff;"}` wrap is needed either. A more specific rule (`.hl` teal emphasis) still wins normally.
  `#2c3e50` remains the *fixed* slate for every deck in this course — don't hand-write a different `background-color`; if you do, its body text falls outside the auto-white rule and needs its own explicit styling (this is the one case still worth a manual look).
  **The one real remaining risk is a stale extension copy** — the same gotcha `pause-dots.lua` hit before: if a deck's local `_extensions/grantmcdermott/clean/` folder predates this filter, dividers silently go back to needing manual styling. Run `python3 check_section_dividers.py <deck>.qmd` (in `quarto_slides/`) any time you're unsure — it verifies the filter is actually wired into that deck's extension copy, and flags the (now rare) case of an explicit non-default `background-color` with unstyled body text. If it reports the extension is stale, re-copy the *whole* `_extensions/grantmcdermott/clean/` folder, don't just add the missing file.
- **NO SLIDE MAY OVERFLOW — this is mandatory, checked, and never left for the user to catch.** A deck is not finished while any slide's content runs past the slide box. After every `quarto render`, run `python3 check_overflow.py <deck>.html` (in `quarto_slides/`) — it loads the deck in headless Chrome with every fragment expanded and reports each slide that spills over. Fix every slide it flags, re-render, re-run, and only call the work done when it prints `✅ no slide overflows`. Do this on a from-scratch deck, a PowerPoint conversion, and after any edit that adds content to a slide — proactively, without being asked. The user has repeatedly had to point out overflowing slides; that must stop.
  - **The shrink ladder, in order:** (1) `{style="font-size: 0.9em;"}` on the `##` heading — scales the whole `<section>`, one clean mechanism. (2) If still flagged, drop it further — `0.85em`, `0.8em`, `0.75em` — until the checker is clean (going below ~0.7em means the slide has too much on it; tell the user rather than shrinking into unreadability). (3) Alongside the font drop: rebalance `layout="[X,Y]"` / `.column width=` proportions (a narrow text column forcing long wraps is often the real culprit), and **cap every image with `max-height` in `vh`** (e.g. `{style="max-height: 32vh; width: auto;"}`) — stacked or side-by-side images are the most common non-text overflow. (4) Tighten `line-height` / list `margin-bottom` before dropping font-size further.
  - Do **not** reach for `{.smaller}` as the default (bigger, less predictable jump) and **never** combine `{.smaller}` with an explicit `font-size` on the same slide — they compound into unreadably tiny.
  - Once the checker is clean, prefer bigger over further cramming — don't shrink a slide that already fits.
- **Known gotchas** (both cost real time this session — check these first when a style change "does nothing" or a pause "doesn't work"):
  - `layout="[X,Y]"` column divs (`::: {#first-column style="..."}`) **silently discard** any custom `style=` placed directly on them, replacing it with an auto-generated `flex-basis` rule. Fix: put the styling on a nested `<div>` *inside* the column instead.
  - **Third-level (and deeper) bullets render as a gray bullet `•`** (level 1 = teal disc, level 2 = teal arrow, level 3+ = muted gray bullet, extra indent). This comes from the `.reveal ul ul ul { list-style: none; … content: $sub-bullet; }` rule in `_extensions/grantmcdermott/clean/clean.scss`. Without it, `ul ul` (which matches *any* depth) gives level 3 the level-2 arrow *plus* reveal's native `circle` marker stacked underneath, which looks like a "circle+arrow blob". `list-style: none` must be set inside the level-3 rule itself. **History:** fixed 2026-10-01 (dash marker); a Dropbox conflicted copy on 2026-10-07 silently reverted the `quarto_slides/` copy to the pre-fix file, so the blob came back (caught on `12_probability` slide 26, 2026-10-15). Re-fixed with a bullet marker at the user's request. **Guard:** `check_overflow.py` now runs `theme_guard()` first and prints a `⚠️ THEME:` warning if the rule is missing or if the `quarto_slides/` and `New_2140_syllabus/slides/` copies of `clean.scss` differ. Treat that warning as a blocker. When editing the theme, always edit both copies (or edit one and `cp` it over). After any Dropbox "conflicted copy" appears in `_extensions/`, diff it against the live file before trusting either one. Write third-level items as plain nested markdown bullets (4-space indent); never type an arrow or dash marker by hand.
  - A CSS rule scoped only by a bare selector (e.g. `#slide-id p { margin: ... }`) can lose to the theme's own `.reveal p` rule. Scope as `.reveal section#slide-id p { ... !important; }`.
  - **Always verify a style/pause change actually landed** — render, then grep the output `.html` for the expected attribute/class. Don't trust that the `.qmd` edit was enough; this project has been burned by "confirmed working" checks that only verified text existed in the HTML, not that it behaved correctly.
  - **A markdown image with non-empty alt/caption text — `![caption](path){style="max-height: Xvh;"}` — puts the `style` on the auto-generated `.quarto-figure`/`<figure>` *wrapper* div, not on the `<img>` itself**, so a `max-height` cap silently does nothing (the wrapper's max-height doesn't constrain a block-level `<img>` inside it) — this is a *different* bug from the `layout=` column gotcha above, and it stacks with it: caught on `10_variable_types.qmd`'s "Check your codebook" slide, where two codebook-cover images with descriptive alt text/citations kept overflowing no matter how small the `max-height` was set, because the size was never actually reaching the image. Fix: use an empty-alt image — `![](path){style="max-height: Xvh;"}` — and put any caption/citation text in a separate fenced div underneath (`::: {style="font-size: 0.55em; text-align: center;"}` / `Caption [@key]` / `:::`), matching the figure-source-line convention already used elsewhere in this project. Verify by grepping the rendered `.html` for `style="max-height` immediately preceding the `<img` tag itself, not just present somewhere nearby.
  - **Closing a gap between two adjacent lines/blocks (the "LaTeX `\vspace{-Npt}`" need) — the general recipe and its two traps**, worked out in full on `10_variable_types.qmd`'s "Different kinds of variables" slide (2026-09-22). The tool: wrap whichever block comes *after* the gap in `::: {style="margin-top: -Npx;"}` / `:::` (or, for a heading, put `margin-top`/`margin-bottom` straight in its own `{style=...}` attribute — heading attributes land on the generated `<section>`/`<hN>` directly). Two things make this fight-the-CSS instead of just-set-a-number:
    1. **Any standalone markdown image — `![](path){...}`, empty alt or not — gets wrapped in a `<p>...</p>` by pandoc** (a lone image is inline content, and inline content standing alone becomes a paragraph). That `<p>` carries the theme's own paragraph margin, entirely independent of any `margin` you put in the image's own `{style=...}`. Zeroing the image's margin does nothing to close a gap caused by this — the `<p>` is what's pushing it away from the heading above. Fix: skip markdown image syntax entirely and use a **single-line** raw HTML wrapper — `<div style="margin: 0;"><img src="..." style="..."></div>` all on one line. (Multi-line — `<div>` / `<img>` / `</div>` on separate lines — still gets an inner `<p>` inserted around the `<img>`; it must be one line to stay a single raw HTML block.) This is a *different* bug from the `.quarto-figure` wrapper gotcha above (that one only hits captioned images and misplaces the `style`; this one hits every standalone image and is about the invisible `<p>` margin, not the image's own style).
    2. **Adjacent margins collapse to whichever is larger, not smaller — so overriding just one side of a boundary can silently do nothing.** A list's `margin-bottom` and the next paragraph's `margin-top` collapse into one gap sized by the bigger of the two; shrinking only the list's side has zero visible effect if the paragraph's default top margin is bigger. Symptom: a margin edit that "does nothing" even though it demonstrably rendered (grep confirms it's in the HTML). Fix: zero **both** sides of every boundary inside the block (e.g. `.fragment p { margin: 0; }` and `.fragment ul { margin: 0.15em 0 0 0; }`), then set the one gap you actually want as a single explicit value on the outer wrapper — `.fragment + .fragment { margin-top: 15px; }` (the `+` selector only matches non-first siblings, so the first block isn't pushed away from the heading above it). **Do not reach for `overflow: hidden` on the wrapper as a shortcut to stop collapsing without also zeroing the inner margins** — it contains the child's margin *inside* the box instead of letting it collapse away, which makes the visible gap bigger, not smaller (this exact mistake shipped once and had to be reverted the same session). After any spacing fix here, verify against the actual text/image edges with `getBoundingClientRect()` in a headless-Chrome probe (`Reveal.slide()` to the id, expand fragments, measure `el.querySelector('p').getBoundingClientRect()`), not just the wrapper divs — a wrapper-to-wrapper measurement can look right while trapped inner margin still makes the real, visible gap bigger.
  - **`getComputedStyle()` read via headless Chrome's `--dump-dom` mode can silently report a stale/wrong `color` value even when the real rendered pixels are correct** — cost most of a debugging session on `10_variable_types.qmd`'s "Different kinds of variables" slide (2026-09-22). Symptom: a `color` CSS rule (even scoped correctly, even with `!important`, even confirmed present and *matching* via `element.matches(selector)` in the same probe) reads back as some unrelated theme default via `getComputedStyle(el).color` in a `--dump-dom` probe — but `el.style.color` (the actual inline value, when set via JS) shows the correct value at the very same instant, in the very same probe. The real, ground-truth answer only showed up in an actual `--screenshot` PNG sampled pixel-by-pixel with PIL (`im.getpixel((x, y))`) — which confirmed the style *was* correctly applied the whole time. This is specific to `getComputedStyle`-for-color read through `--dump-dom`; the geometry-based checks elsewhere in this file (`getBoundingClientRect()` for margins/gaps, also via `--dump-dom`) have been reliable all session and are not in question. **When verifying a `color` (or likely other paint-only, non-layout) style change, don't trust a `--dump-dom` + `getComputedStyle` probe alone** — take a real `--screenshot` and sample actual pixel values (or at minimum eyeball it) before concluding a style fix didn't work. Geometry probes (`getBoundingClientRect`) remain trustworthy via `--dump-dom`.
  - **To highlight only the most-recently-revealed fragment and dim everything shown before it** (e.g. "gray out past bullets, keep the current one dark"), plain CSS targeting reveal.js's own `.visible` / `.current-fragment` classes (`.fragment.visible { color: gray }` / `.fragment.current-fragment { color: black }`) can fail to take effect for reasons not fully isolated (not a specificity problem — confirmed matching, confirmed `!important`, still lost to something). **The reliable fix is JS, driven by reveal's own fragment events**, setting `element.style.color` directly (inline styles set via JS aren't subject to whatever was blocking the CSS route):
    ```html
    <script>
    (function () {
      function init() {
        if (!(window.Reveal && Reveal.isReady && Reveal.isReady())) { setTimeout(init, 100); return; }
        var el = document.getElementById('SLIDE-ID');
        if (!el) return;
        function apply() {
          el.querySelectorAll('.fragment').forEach(function (f) {
            if (f.classList.contains('current-fragment')) f.style.color = '#1a1a1a';
            else if (f.classList.contains('visible')) f.style.color = '#999999';
            else f.style.color = '';
          });
        }
        Reveal.on('fragmentshown', apply);
        Reveal.on('fragmenthidden', apply);
        apply();
      }
      init();
    })();
    </script>
    ```
    Target **every** `.fragment` element (outer blocks *and* any nested fragment spans inside them, e.g. a click-revealed answer inside a bullet), not just the top-level ones — `color` is inherited, so a nested fragment left unstyled will visually inherit whatever gray/black its dimmed-or-not ancestor currently has, which looks wrong the moment the nested one becomes current. Setting every fragment's own color explicitly sidesteps that inheritance entirely, since JS sets it per-element regardless of ancestor state.
  - **An illustrative (non-executable) code block — bare `` ```r `` with no curly braces, used throughout this deck to *show* R syntax without running it — silently becomes a real executing knitr chunk if a stray trailing space sneaks onto the fence line (`` ```r `` with a trailing space instead of `` ```r``).** Broke `9_lab_r-introduction.qmd` on 2026-09-22 (a concurrent RStudio edit introduced the trailing space): the block was `var <- data$variable`, meant purely as a syntax example, but it actually executed against R's built-in `data()` function (never assigned to a real data frame), erroring `object of type 'closure' is not subsettable` and halting the whole render. None of this deck's other ~14 identical bare-`` ```r `` illustrative blocks had the trailing space, and none were affected — this is specific to that one fence line, not a systemic issue. **Fix, and the more robust form to use going forward:** write illustrative-only blocks as `` ```{.r} `` (dot-prefixed language *class*, in braces) instead of bare `` ```r `` — `{.r}` is unambiguously non-executable under every pandoc/quarto parse path (only a brace-wrapped engine name *without* a leading dot, `{r}`, is ever executable), so a stray trailing space or other whitespace variation can't accidentally flip it into a real chunk.   - **`check_overflow.py`'s print-pdf measurement carries a fixed, deterministic baseline offset on every deck using this theme's footer** (measured as +113px in practice) — every ordinary content slide's `scrollHeight` reads that much taller than the configured slide height regardless of actual content, while level-1 divider slides read differently again. This isn't knitr-specific or a settle-timing race (confirmed present, unchanged, at settle delays up to 16s, and on a plain non-knitr deck — `7_theory_development.qmd`, 2026-09-17) — it's baked into how print-pdf mode measures against the configured height whenever a footer is present. The script (rewritten 2026-09-17) no longer discards a read just because many slides share one value; it treats a majority-shared value as the baseline, subtracts it from every slide, and only flags what's left over the tolerance — real overflow always survives that subtraction since it varies slide-to-slide with actual content. A read is only discarded now if no value has a solid majority (genuinely unsettled). If you ever see the raw (pre-fix) symptom again — many/most slides reporting one identical `+Npx` value — that's this baseline, not real overflow; don't hand-wave past it, but don't panic-shrink content either.
  - **`check_overflow.py` also never force-loaded reveal.js's lazy (`data-src`, not yet promoted to `src`) images before measuring** (fixed 2026-09-21) — an unloaded `<img>` has no intrinsic size, so any `max-height` cap on it constrains nothing, and the slide reads artificially short. Symptom: resizing an image on a flagged slide appears to do *nothing at all* to the reported overflow, however much you shrink it. The script now does `document.querySelectorAll('img[data-src]').forEach(img => img.src = img.dataset.src)` right before measuring. If a future copy of the script regresses on this, the tell is the same as above — real content edits producing zero change in the reported number.
  - **A single knitr-generated figure can fail to embed into a `self-contained` render**, leaving a dead local `src="<deckname>_files/figure-revealjs/unnamed-chunk-N-1.png"` reference instead of a `data:` URI (seen once on `9_lab_r-introduction.qmd`, likely a Dropbox-sync race against quarto's write-then-clean pattern for this project's Dropbox-backed folder). After every render of an R-chunk deck, verify with `grep -o 'src="<deckname>_files[^"]*"' <deckname>.html` — any match means a broken image; re-render (repopulating the images folder per the gotcha above first) until the grep comes back empty.
  - **A demo chunk showing students `read_csv("data.csv")` should carry `#| eval: false`** (that literal path doesn't exist in the deck's working directory) — but if any *later* chunk actually uses the resulting object (`nrow(anes)`, `table(anes$partyid)`, a `ggplot(anes, ...)`, etc.), that object was never created and `quarto render` hard-fails with `object 'anes' not found`. Fix: immediately after the illustrative `eval: false` chunk, add a hidden `#| echo: false` chunk that actually loads the real data from its real path (e.g. `../2140_data/anes_2024/anesdata_2024.csv`) into that same object name. This broke `9_lab_r-introduction.qmd` on 2026-09-17 — the hidden loader chunk had gone missing (likely lost during an earlier edit/bisect session) while the illustrative `eval: false` chunk and every downstream chunk depending on `anes` stayed in place, so render failed. The setup chunk right after the YAML header (copies static images from `<deckname>_assets/images/` into `<deckname>_files/images/`, see gotcha above) had also gone missing at the same time — check for **both** any time this deck (or a future knitr deck built the same way) "stops rendering" with no `.qmd` diff the user is aware of.

Reference implementation: **`6_survey_data.qmd`** — the "Explore ANES: political ideology" → "Click a point on the scale" → "Try it yourself" sequence, plus the "Find your own variables" QR slides. Copy from those slides rather than rebuilding from scratch.

Tabulate the real variable with a throwaway Python/Rscript (verify the exact question wording from the PDF codebook, and the exact variable ID — e.g. ANES `V241177` = 7-pt liberal-conservative self-placement — not memory), then embed the counts. Online fallbacks: ANES per-variable pages at `sda.berkeley.edu/sdaweb/docs/anes2024full/DOC/hcbk00NN.htm`; WVS docs at `worldvaluessurvey.org/WVSContents.jsp?CMSID=Documentation`. If you can't verify a distribution, say so and build the slide around variable *structure* (categories, recoding, IV/DV fit) instead of fabricated statistics. Codebook %s are usually on a valid-response base (excluding refused/error); a raw `count()` on all rows differs by a few tenths — note which base you used and that figures are unweighted.

**Interactive category explorer** (the "click a point on the scale" widget): a `<div>` mount + an inline `<script>` that `document.createElement`s one clickable box per response category; clicking one highlights it (teal `#107895` active) and rewrites a detail panel with that category's real `% (n=…)`, a proportional mini-bar, and a one-line measurement/recoding note. Guard re-init with `if (mount.dataset.loaded) return;`. Pure vanilla JS — no libraries, survives `self-contained`.

**In-deck chart via R/ggplot.** Adding *any* `{r}` chunk switches `quarto render` to the knitr engine — needs R + `tidyverse` installed (`Rscript -e 'install.packages("tidyverse")'` once). Chunk pattern: `#| echo: true` (or `#| echo: false` for a static chart with no code-toggle), `#| fig-width` / `#| fig-height`, `#| out-width: "100%"`; in the plot use `theme_minimal()` + `plot.background`/`panel.background = element_rect(fill = "transparent", color = NA)` so it sits on the slide, and `fill = "#107895"` (a distinct grey `#999999` for a "DK"/missing or second series) to match the deck. When you don't have the raw data file, hardcode **verified** summary counts in a `tibble()` — `geom_col()` straight off the counts (fast), or `tidyr::uncount()` → `geom_bar()` if you need respondent rows. Keep axis labels short — a long `labs(x=...)` gets clipped at narrow `fig-width`.

- **Several variables side by side** (e.g. WVS `Q243` & `Q249` on the same 1–10 scale): one tibble with a `variable` column, `geom_col()` + `facet_wrap(~variable)`, `fig-width` ~7. See `6_survey_data.qmd`'s "Q243 & Q249: essential to democracy?" slide.
- **Two groups compared** (e.g. US vs. another country): add a `country` column, `geom_col(position = "dodge")` + `scale_fill_manual(values = c(...))` with `#107895` / `#999999`, plot **percent within group** (`mutate(pct = 100*n/sum(n))`) not raw counts when the group Ns differ. See the "US vs. Germany" slide.
- **WVS Wave 7 country coverage:** 64 countries, **no Nordic countries** (Sweden/Norway/Denmark/Finland absent). Before promising a specific country comparison, check `B_COUNTRY_ALPHA` in the CSV; nearest Western-European democracies present are Germany (`DEU`), Netherlands (`NLD`), Great Britain (`GBR`).
- The pooled/analysed CSVs are large (WVS ~180 MB) and not on GitHub Pages — never read them in a render-time chunk; extract the marginals once with a throwaway script and embed the counts, the same way the ANES slide does.

**Click-to-swap plot ↔ code** (from `6_survey_data.qmd` slide 8): scope the `<script>` by the slide's **section id** (the heading slug, e.g. `#click-a-point-on-the-scale`) — **not** `#second-column`, which is reused across slides and isn't unique. Grab `.code-copy-outer-scaffold` (the source block) and `.cell` (the plot wrapper), `insertBefore` the code block into the plot's slot, give the code `width: fit-content` so its right border ends after the code, then two functions — clicking the image runs `showCode()` (hide `.cell`, show code), clicking the code runs `showPlot()` (reverse). Exactly one is visible at a time; the code drops in exactly where the plot was. Put the plot/chart column in a `.fragment` so it appears after the interactive widget.

**Find-your-own-variables slides.** For the in-class "search the codebook for your topic" exercise: generate QR codes locally with Python `qrcode` (`pip3 install qrcode`), save PNGs into `<deckname>_files/images/`, embed as plain `<img>` (Quarto base64s them). One QR per resource (full codebook, short variable list). Follow with a "topic → variable" slide giving a verified `Vxxxxxx`/`Qxxx` starting point per topic, flagged as *starting points, verify wording in the codebook*.

## Converting a PowerPoint (summary — read `PPTX_CONVERSION_RULES.md` for the full method)

1. Confirm the source file in `for_quarto_convert/` (check for duplicate/dated variants — ask which is canonical, don't guess).
2. Unzip the `.pptx` and parse each slide's XML with a proper XML parser (not regex) to get: paragraph text/levels, image relationships, and — critically — the `<p:timing>` block's ordered `clickEffect` groups (each group's `spid`s are one pause step, in document order).
3. Extract/convert images into `<deckname>_files/images/`; convert any non-web format (TIFF, etc.) to PNG.
4. Build the `.qmd`: standard opener → converted content (click order → pauses, per Core conventions above; every line of visible original text preserved, shrunk rather than cut/moved/split) → TL;DR → References.
5. For very large decks (40+ slides spanning multiple class sessions), check with the user before converting whether it should be one deck or split — and convert/report in chunks rather than all at once.
6. Render, then run `python3 check_overflow.py <deck>.html` and `python3 check_section_dividers.py <deck>.qmd` (the latter mainly confirms the deck's extension copy has the automatic divider filter, not a manual styling pass), fixing everything either flags, until both print clean. Then spot-check the dense/multi-image slides — first-pass conversions still routinely need a layout pass from the user afterward, but never one that leaves a slide overflowing.
7. Leave the source `.pptx` in `for_quarto_convert/`; put the output `.qmd`/`.html`/images in `quarto_slides/` (not inside `for_quarto_convert/`).
